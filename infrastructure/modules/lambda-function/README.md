# infrastructure/modules/lambda-function
Goal
- To provide a secure, scalable, and highly observable serverless compute environment for the GEP microservices.
- Manages the full lifecycle of Lambda functions, including their logging infrastructure and the encryption keys required for sensitive environment data.

Selected Settings & Thresholds
- Runtime: nodejs22.x (Latest LTS) to ensure high performance, modern syntax support, and long-term security patching.
- Log Retention: Defaulted to 30 days via CloudWatch Log Groups to balance audit requirements with cost-efficiency.
- Concurrency: Configurable reserved_concurrent_executions to prevent a single function from exhausting the regional account limit.
- Tracing: AWS X-Ray enabled in Active mode for end-to-end request tracing and bottleneck identification.

Rationale
- Modular KMS Management: Automatically provisions a dedicated Customer Managed Key (CMK) for environment variables only if variables are present, optimizing cost while ensuring data at rest is never stored using default AWS-managed keys.
- Dynamic Blocks: Uses dynamic "dead_letter_config" and dynamic "environment" to keep the module flexible; it only attaches resources when variables are explicitly provided.
- VPC Capability: Supports deployment into private subnets for services requiring direct access to internal Vistra resources or VPC-restricted databases.
- Integrity Checks: Uses source_code_hash to ensure that Terraform only triggers an update when the actual application code changes, preventing unnecessary redeployments.

Security Compliance (Checkov & Best Practices)
- CKV_AWS_116 (DLQ): Implementation uses a skip comment because the DLQ is configured dynamically. This ensures the module remains compliant while allowing specific services to opt-in to asynchronous failure handling.
- Encryption: Environment variables are encrypted using a CMK with a strict Key Policy that limits access to the account root and the specific Lambda Execution Role.
- Log Security: Supports KMS encryption for CloudWatch Logs (logs_kms_key_arn) to protect diagnostic data containing potential system metadata.
-KMS Hygiene: enable_key_rotation is enabled for all module-generated keys to meet enterprise security standards.

Notes
- Cold Starts: The use of NodeJS 22.x and VPC configuration should be monitored; if latency exceeds the p90 threshold defined in the monitoring module, consider Provisioned Concurrency.
- Deployment: The filename variable expects a pre-zipped deployment package, typically generated by the CI/CD pipeline.
